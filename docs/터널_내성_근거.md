# 터널 내성 근거와 경로 판단 기준

11월 5일에 "꼭 지나갈 경로"와 "꼭 피할 경로"를 어떤 기준으로 나눌지 찾아본 기록입니다. 의료 조언이 아닙니다.

이후 팀 문헌 검토 보고서를 기준으로 다시 정리한 내용은 [터널_통과_로직.md](터널_통과_로직.md)에 있습니다. 두 문서가 다르면 그쪽을 따라 주세요.

## 결론

환자가 터널을 몇 m, 몇 분까지 견디는지 잰 연구는 찾지 못했습니다. 그래서 임상 한도를 만들어 넣지 않았습니다. 운전자가 고른 시작 한도에서 출발해 본인의 통과 평가로 조금씩 조정합니다. 앱에 들어간 계수는 모두 근거를 참고해 우리가 정한 값이고 아직 검증되지 않았습니다.

## 근거 표

등급은 우리 기능에 바로 쓸 수 있는 정도를 뜻합니다.

| 내용 | 대상 | 터널프리 적용 | 등급 | 출처 |
|---|---|---|---|---|
| 터널 주행이 불편한 사람은 인구의 약 10~20%로 대략 추정된다. 고령층 최대 40%가 매우 불안하다고 답했다. | 노르웨이 일반 운전자, 추정치 | 대상 규모 설명 | 중간 | [SINTEF 보도, 2010](https://www.sciencedaily.com/releases/2010/03/100304075712.htm) |

| 나선 터널에서 길이가 길수록 평균 심박이 높고 심박변이도가 낮았다. | 일반 운전자 30명 | 길이를 위험 요인으로 사용 | 중간 | [Accident Analysis & Prevention 2025](https://www.sciencedirect.com/science/article/abs/pii/S0001457525000697) |

## 찾지 못한 자료

- 환자군의 터널 길이별 불안 점수나 공황 발생률
- 몇 초 또는 몇 m가 안전한 한도인지 정한 임상 기준
- 한국 장대터널에서 공황장애 운전자를 측정한 연구
- 정체로 터널 안에 멈췄을 때의 불안 정량 자료. 칼럼 수준의 임상 경험만 확인했다.

19440895 논문과 StatPearls 공황장애 원문은 자동 접근이 막혀 검색 요약으로만 봤습니다. 제출 전에 누군가 직접 열어 확인해 주세요.

## 경로 판단 기준

앱은 경로마다 터널 개수, 가장 긴 터널, 총 터널 길이를 계산합니다. 통과 시간은 시속 60 km로 잡습니다.

| 입력 | 처리 | 성격 |
|---|---|---|
| 회피 강도 | 시작 한도 0 m, 300 m, 1 km, 3 km, 회피 안 함 | 사용자 선택 |
| 통과 평가 "힘들었음" | 한 번에 그 길이의 70%로 낮춤. 터널이 지금 한도의 1.5배보다 길면 낮추지 않음 | 설계 가정값 |
| 통과 평가 "괜찮음" | 한도 이상인 터널에서 2회 쌓이면 그 길이의 150%로 올림 | 설계 가정값 |
| 오늘 상태 힘듦 | 한도 × 0.5 | 설계 가정값 |
| 야간(해가 진 뒤~뜨기 전) | 한도 × 0.7 | 설계 가정값, 직접 근거 없음 |
| 동승자 있음 | 2026-11-08부터 계수 대신 동행 한도를 따로 둔다. [터널_통과_로직.md](터널_통과_로직.md)의 "출발 전 판단" | 근거 21 |
| 응급 이송 | 추가 5분 이내만 회피 | 설계 가정값 |
| 시간 제한 | 추가 15분 초과면 운전자 선택 | 설계 가정값 |

판정 순서는 이렇습니다.

1. 최단 경로에 터널이 없으면 차이 없음이다.
2. 오늘 한도로 피하는 경로가 없으면 터널 꼭 지나가기다. 가장 긴 터널의 통과 시간을 미리 알린다.
3. 응급 이송이면 5분 이내로 늦어질 때만 피하고, 넘으면 지나간다.
4. 가장 긴 터널이 오늘 한도를 넘으면 터널 꼭 피하기다. 시간 제한이 있고 15분 넘게 늦어지면 직접 선택이다.
5. 한도 안이고 피하는 경로의 터널이 같으면 차이 없음, 다르면 직접 선택이다.

어떤 판정이 나오든 마지막 선택은 운전자가 합니다.

## 검증 계획

시간이 되면 제출 전에, 아니면 공모전 뒤에라도 해 보면 좋겠습니다.

1. 정신건강의학과 또는 임상심리 전문가에게 계수와 문구 자문을 받는다.
2. 동의한 사용자의 통과 평가를 익명으로 모을 때 연구 윤리 절차를 확인한다.
3. 기록은 기기 안에 두고, 외부 전송은 건강정보 처리 검토 뒤에 결정한다.
