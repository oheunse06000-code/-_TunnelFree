## Part 1. 기존 코드 숙지 (`lib/main.dart`, 1,610줄 단일 파일)

### 1-1. 전체 구조 한눈에

```
main()                       → runApp(TunnelFreeApp)
TunnelFreeApp (Stateless)    → MaterialApp, home = TunnelFreePage
DemoPlace / DemoRoad         → 체험용 장소 10개, 도로 11개 (1→3 구간만 tunnel: true)
distanceBetween()            → 하버사인 거리(m)
TunnelFreePage (Stateful)
└ _TunnelFreePageState       → 앱 로직 전부 (상태, 경로, 모의주행, 음성, 지도, UI)
```

핵심 아이디어: 실제 GPS는 표시만 하고, 경로·주행은 체험용 그래프 위에서 시뮬레이션한다. 지도는 카카오맵 JS를 WebView에 띄우고 Dart가 JSON을 넘겨 그린다.

### 1-2. 상태 변수 (115~160행)

| 변수 | 역할 |
|---|---|
| `_speech`, `_tts` | speech_to_text, flutter_tts 인스턴스 |
| `_map` | InAppWebViewController. 지도 JS 호출용 |
| `_currentPosition`, `_positionSubscription` | geolocator 실제 GPS |
| `_driveTimer` (250ms), `_breathTimer` (1s) | 모의 주행 틱, 호흡 안내 틱 |
| `_avoidTunnel` | 터널 회피 옵션 (기본 true) |
| `_running`, `_paused`, `_helpOpen` | 주행 중 / 일시정지 / 도움 다이얼로그 열림 |
| `_destination`, `_via`, `_currentNode` | 목적지·경유지·현재 노드 인덱스 (`places` 기준) |
| `_route` | 남은 경로 노드 리스트. 항상 `_route[0]→_route[1]` 구간을 이동 중 |
| `_fraction` | 현재 구간 진행률 0~1 |
| `_speechGeneration` | TTS/STT 취소용 세대 카운터. 값이 바뀌면 진행 중이던 음성 작업이 스스로 중단 |
| `_lastCommand`, `_lastCommandAt` | 같은 음성 명령 2초 내 중복 실행 방지 |

### 1-3. 기능별 메서드 지도

(A) 경로 탐색, 340~470행
- `_road(a,b)`: 두 노드를 잇는 DemoRoad 찾기
- `_findPath(start,end)`: 다익스트라. `_avoidTunnel`이면 `road.tunnel` 도로를 건너뜀 → 이것이 "터널 회피"의 전부
- `_calculateRoute(dest, via)`: 주행 중이면 현재 이동 중인 구간(`_route[0..1]`)을 prefix로 유지한 채 재계산(순간이동 방지). 경유지가 있으면 start→via→dest 두 번 탐색
- getter: `_position`(구간 보간 좌표), `_remainingDistance`, `_tunnelCount`, `_insideDemoTunnel`, `_remainingMinutes`(40km/h 고정)

(B) 목적지·옵션·경유지, 473~530, 657~710행
- `_selectDestination(i)`: 경로 계산 후 "체험 경로에 터널이 N개" TTS
- `_changeAvoidance(bool)`: 옵션 변경 + 경로 재계산
- `_addVia(i)` / `_removeVia()`: 화장실(8), 휴게시설(9) 경유

(C) 모의 주행, 530~657행
- `_startDrive()` → `_startTimer()` → 250ms마다 `_advance()`
- `_advance()`: 40km/h×10배속으로 `_fraction` 증가, 구간 끝나면 `_route.removeAt(0)`. 경유지 도착 시 자동 일시정지, 목적지 도착 시 종료. 매 틱 `_syncMap()`
- `_togglePause()`, `_endDrive()` (모든 상태 초기화)

(D) 음성, 250~335, 751~905행
- `_prepareVoice()`: TTS ko-KR, 속도 0.45
- `_say(text)`: STT 취소 → TTS 재생. `_speechGeneration` 체크로 중간 취소
- `_listen()`: STT 초기화/시작, 결과를 `_handleCommand`로
- `_handleCommand(raw)`: 공백 제거 후 키워드 contains 매칭 (정규식). 우선순위: 도움 요청(`무서워|숨이막|도와`) → 종료 → 일시정지 → 출발 → 터널 회피/허용 → 화장실/휴게소 → 경유 취소 → 호흡 → 목적지 이름. 매칭 실패 시 안내 메시지

(E) 안심 기능, 711~750, 906~976행
- `_toggleBreathing()`: 들이쉬기 4초/내쉬기 6초 10초 주기 텍스트 + TTS 시작 안내
- `_openHelp()`: 주행 일시정지 + 다이얼로그(보호자 전화 / 119). `_call()`은 `tel:` URL로 전화 앱만 연다 (자동 신고 없음)

(F) 지도, 1040~1370행
- `_buildHtml()`: 카카오맵 JS SDK를 포함한 HTML 문자열 생성. `kakaoJavaScriptKey` 사용. JS 쪽에 `window.updateDemo(payload)` 정의
- `_syncMap(fit)`: `{position, path, fit, follow, dark}` JSON을 `evaluateJavascript`로 전달. `dark: _insideDemoTunnel` → 터널 구간이면 지도 어둡게
- `_mapView()`: InAppWebView + `mapReady` JS 핸들러로 준비 신호 수신

(G) UI, 1370~1610행
- `_panel()`: 주행 전(검색, 목적지 목록, 터널 회피 토글) / 주행 중(남은 거리·터널 수, 일시정지, 호흡, 도움) 분기
- `build()`: AppBar(설정) + 지도 + 패널

### 1-4. 코드 읽기 순서 추천 (약 1시간)
1. 36~106행 데이터 모델 → `roads`에서 어느 구간이 터널인지 확인
2. `_findPath` → `_calculateRoute` → `_selectDestination` (경로 흐름)
3. `_startDrive` → `_advance` (주행 흐름)
4. `_handleCommand` (음성 명령 목록)
5. `_syncMap` + `_buildHtml`의 `updateDemo` 함수 (지도 연동)
6. `_panel` (버튼이 어느 메서드를 부르는지)

### 1-5. 알아둘 한계 (기획서·PT에서 솔직히 말할 것)
- 터널 데이터는 하드코딩 1개 구간. 실제 터널 DB·경로 API 없음
- 모의 주행이며 실제 GPS 위치와 경로가 분리되어 있음
- 급정거 감지 없음. 공황/교통 판별 미구현
- 단일 파일이라 Pleos 전환 시 기능별 파일 분리 권장

## Part 2. Pleos 사용법

### 2-1. Pleos Fleet과 Pleos Connect의 차이
- 링크하신 Pleos Fleet(pleos.ai/service-solution/pleos-fleet)은 기업용 차량 관제(FMS) 서비스와 그 API입니다. 차량 안에서 도는 앱을 만드는 것과 무관합니다.
- 공모전이 요구하는 것은 Pleos Connect (차량 인포테인먼트 OS, AAOS 기반)와 Pleos Connect SDK입니다. 개발자 포털은 Pleos Playground (https://pleos.ai/playground → developers.pleos.ai), 문서는 https://document.pleos.ai 입니다.
- 공모전이 허용한 SDK 5종: Vehicle, NaviHelper, TextToSpeech, SpeechToText, FusedLocation.

### 2-2. 기본 사실
| 항목 | 값 |
|---|---|
| 기반 | Android Automotive OS. Kotlin/Java 네이티브 Android 앱 |
| 최소 요건 | minSdk API 28, Gradle 8.0+, Android Studio 최신 |
| 에뮬레이터 | Pleos Connect v2.1.0 (Automotive form factor, API 34 system image) |
| Maven 저장소 | `https://nexus-playground.pleos.ai/repository/maven-releases/` |
| 패키지 그룹 | `ai.pleos.playground` (예: `ai.pleos.playground:Vehicle:2.3.2`) |
| 권한 | `pleos.car.permission.*` 를 Manifest에 선언. Pleos App Market과 사전 승인된 범위만 사용 가능 |
| 시작 문서 | https://document.pleos.ai/docs/pleos-only/getting-started |
| Flutter 지원 | 문서에 언급 없음. 모든 가이드가 Kotlin/Java 전제 |

### 2-2-1. 이 노트북에서 에뮬레이터가 안 뜰 때 (2026-11-04 해결 기록)

증상: WHPX "operational"인데 adb offline, 커널 출력 0, QEMU 메모리 400MB에서 정지.
원인 두 가지가 겹쳐 있었고 둘 다 해결해야 부팅됨.

1. 코어 격리 → 메모리 무결성(HVCI) 끄기 후 재부팅. (Windows 보안 UI에 항목이 안 보이면 관리자 PowerShell에서
   `Set-ItemProperty 'HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity' -Name Enabled -Value 0`)
2. SDK·AVD 경로에 한글이 없어야 함. 사용자 폴더가 `C:\Users\김재승` 이라 기본 경로가 전부 한글.
   - 정션: `mklink /J C:\AndroidSdk C:\Users\김재승\AppData\Local\Android\Sdk`
   - 사용자 환경 변수: `ANDROID_SDK_ROOT=C:\AndroidSdk`, `ANDROID_HOME=C:\AndroidSdk`,
     `ANDROID_AVD_HOME=D:\Android\emu-home\avd`, `ANDROID_EMULATOR_HOME=D:\Android\emu-home`
   - AVD 본체는 `D:\Android\avd\*.avd`, ini는 `D:\Android\emu-home\avd\*.ini`
   - Android Studio: File → Settings → Languages & Frameworks → Android SDK → 경로를 `C:\AndroidSdk` 로 변경, 재시작
   - `pleos-app/local.properties` 의 `sdk.dir=C:\AndroidSdk`

3. Gradle 단위 테스트가 `ClassNotFoundException: GradleWorkerMain` 으로 실패하면 역시 한글 경로 문제.
   테스트 워커의 클래스패스 인자 파일(UTF-8)에 한글 경로가 들어가면 워커 JVM이 MS949로 읽어 깨진다. 정션으로는 해결 안 됨(Gradle이 실제 경로로 되돌림).
   - 프로젝트를 `D:\hmg_contest\` 로 이동 (완료)
   - Gradle 홈을 `D:\gradle-home` 으로 이동 + 사용자 환경 변수 `GRADLE_USER_HOME=D:\gradle-home` (완료)
   - 명령줄 JDK: `JAVA_HOME=C:\Users\김재승\.jdks\jbr-21.0.11` (Gradle 8.14는 Java 25/26 거부)

명령줄 실행/설치:
```
C:\AndroidSdk\emulator\emulator.exe -avd TunnelFree34 -no-snapshot
C:\AndroidSdk\platform-tools\adb.exe install -r app\build\outputs\apk\standard\debug\app-standard-debug.apk
```
API 37 이미지는 RAM 4GB를 강제하므로 API 34 AVD(TunnelFree34)를 쓴다. 에뮬레이터 프로세스를 죽일 때 Git Bash의 `taskkill /F`는 옵션이 경로로 바뀌어 안 먹힘 → PowerShell `Stop-Process -Name qemu-system-x86_64 -Force`.

### 2-3. 개발 환경 세팅 (순서대로)
1. Android Studio 설치 후 Tools → SDK Manager → SDK Update Sites 탭 → `+`
   - Name: `Pleos Connect System Image`
   - URL (Windows): `https://nexus-playground.pleos.ai/repository/raw-releases/connect-avd/2.x/crp-sys-img.xml`
2. SDK Platforms 탭 → Show Package Details → API 34의 Pleos Connect system image 체크 → 설치 → 재시작
3. Tools → Device Manager → Create device → Form Factor Automotive → `Pleos Connect v2.1.0` → Advanced: Default boot Cold, RAM 4GB → system image `Pleos Connect v2.1.0 APIs` → Finish
4. AVD 실행. 부팅 확인
5. Pleos Playground에서 My Project 생성 및 SDK 사용 신청 (https://document.pleos.ai/docs/pleos-only/create-my-project). TTS 서버 모드 등은 여기서 받은 자격 증명이 필요
6. 새 프로젝트: File → New Project → Automotive 카테고리 → Empty Activity → Kotlin → minSdk 28

### 2-5. SDK별 사용 패턴 (공통: 생성 → initialize → 리스너 등록 → 호출 → 해제)

Vehicle SDK, 차량 상태. 도메인: Brake, CarInfo, Door, DrivingMode, Light, TurnSignal, Safety 등
```kotlin
val vehicle = Vehicle(context)
vehicle.initialize()
val brake = vehicle.getBrake()          // 도메인 객체는 getXxx()로만 획득
// 각 도메인은 checkXxxCapabilities / getXxx / setXxx / 리스너 제공
// 결과는 onComplete / onFailed 비동기 람다. 콜백 끝나기 전 release() 금지
vehicle.release()                       // onDestroy
```
Manifest: `<uses-permission android:name="pleos.car.permission.CAR_DOORS" />` 처럼 도메인별 권한 (목록: /docs/pleos-only/connect-sdk-pleos/Vehicle/vehicle-permission)

FusedLocation SDK, 차량 위치 (권한 `pleos.car.permission.FUSED_LOCATION`)
```
FusedLocation(context) → isSupported() → initialize()
→ getLastKnownLocation() 또는 registerFusedLocationCallback()
→ addProximityAlert() / removeProximityAlert()   ← 터널 진입 지오펜스에 바로 쓸 수 있음
→ unregisterFusedLocationCallback() → release()
```
결과 `LocationData`: 위도, 경도, 고도, 진행 방향, 신뢰도, 타임스탬프

NaviHelper SDK, 기본 내비 제어
```
NaviHelper → initialize() → addListener(NaviHelperEventListener) → API 호출 → removeListener() → release()
```
기능: 목적지 설정/확인/취소, 경로 옵션 변경·재탐색, 경유지 추가/조회/제거, 경로 탐색·주행 상태 이벤트, 내비 화면 요청.
세부 시그니처: /docs/pleos-only/connect-sdk-pleos/NaviHelper/destinations, /routes, /waypoint-settings

TextToSpeech SDK
```kotlin
import ai.pleos.playground.tts.TextToSpeech
import ai.pleos.playground.tts.constant.Mode
val tts = TextToSpeech(applicationContext, Mode.ON_DEVICE)  // HYBRID(기본)/SERVER/ON_DEVICE
tts.initialize(); tts.addEventListener(...); tts.setLocale(...); tts.speak(text); tts.stop(); tts.release()
```
ON_DEVICE 모드는 네트워크·앱 등록 없이 동작 → 에뮬레이터 시연에 안전.

SpeechToText SDK, `ai.pleos.playground.stt`, 결과는 `ResultListener`. 문서: /docs/pleos-only/connect-sdk-pleos/SpeechToText/intro

### 2-6. 터널프리 기능 ↔ Pleos SDK 매핑 (현재 코드 어디를 대체하는가)

| 현재 코드 | 대체 SDK | 비고 |
|---|---|---|
| `_findPath` 다익스트라 + `DemoRoad.tunnel` | NaviHelper 경로 옵션·경유지 | 기본 내비가 터널 회피 옵션을 직접 지원하는지 문서 확인 필요. 없으면 경유지 삽입으로 우회 유도 |
| `geolocator` `_getCurrentLocation` | FusedLocation `registerFusedLocationCallback` | |
| `_insideDemoTunnel` 판정 | FusedLocation `addProximityAlert` | 터널 입구 좌표 DB 필요 |
| `flutter_tts` `_say` | TextToSpeech ON_DEVICE | |
| `speech_to_text` `_listen` | SpeechToText | 명령 매칭 로직 `_handleCommand`는 그대로 이식 가능 |
| (없음) 급정거 감지 | Vehicle Brake / CarInfo 도메인 | 속도·브레이크 신호 API 존재 여부를 API Reference에서 확인 |
| `launchUrl(tel:)` | Android `Intent.ACTION_DIAL` | 차량 OS에서 전화 앱 허용 여부 확인 |

### 2-7. 전환 전략 결정 (12/3 PT 전까지)

옵션 A. Flutter 유지 + MethodChannel
- Flutter의 `android/` 모듈에 Pleos SDK 의존성 추가, Kotlin에서 SDK 호출, Dart와 MethodChannel/EventChannel로 통신
- 장점: 기존 UI·로직 재사용. 단점: Pleos가 Flutter를 공식 지원하지 않아 심사·앱마켓 입점 시 리스크. 에뮬레이터(Automotive, API 34)에서 Flutter 엔진이 정상 동작하는지 먼저 검증 필요

옵션 B. Kotlin 네이티브로 재작성 (권장)
- 공모전·Pleos 문서 전제와 일치. 기술 활용성 점수에 유리
- 이식 범위가 크지 않음: 그래프 탐색 100줄, 명령 매칭 90줄, 모의 주행 100줄 + Compose UI. 지도는 카카오맵 Android SDK 또는 NaviHelper의 내비 화면 요청으로 대체
